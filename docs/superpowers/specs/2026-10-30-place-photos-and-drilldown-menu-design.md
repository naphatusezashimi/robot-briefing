# รูปสถานที่ในคำตอบ + เมนูกดแตกหมวด (ที่เที่ยว / ของฝาก สระบุรี)

วันที่: 2026-10-30
สถานะ: อนุมัติแล้ว (2026-10-30)

## ทำไมต้องทำ

คนที่มายืนหน้าหุ่นแล้วถามเรื่องที่เที่ยวสระบุรี อยากเห็นว่าสถานที่หน้าตาเป็นยังไง ไม่ได้อยากฟังคำบรรยายอย่างเดียว อีกเรื่องคือคนที่ไม่รู้จะถามอะไร ควรกดเลือกจากเมนูได้เลย กด "ที่เที่ยว" แล้วไล่ลงไปเป็น "น้ำตก" "วัด" ... จนเจอสถานที่ที่สนใจ

ข้อจำกัดใหญ่คือ **โควตา Gemini ฟรีมีแค่ประมาณ 20 คำถามต่อวัน** ฟีเจอร์นี้ต้องไม่ทำให้เรียก AI บ่อยขึ้น ส่วนเมนูยิ่งดี ถ้าตอบได้โดยไม่ต้องเรียก AI เลย

## เป้าหมาย

1. **รูปต่อท้ายคำตอบ AI:** ถามถึงสถานที่หรือของฝากที่มีใน `saraburi_data.json` ไม่ว่าจะพูดหรือพิมพ์ จะมีรูปของที่นั้นต่อท้ายคำตอบ
2. **เมนูกดแตกหมวด:** มีสองเมนูคือ "ที่เที่ยวสระบุรี" กับ "ของฝากสระบุรี" กดแล้วได้หมวดย่อย กดหมวดได้รายชื่อพร้อมรูปเล็ก กดชื่อได้การ์ดรายละเอียดพร้อมรูปใหญ่
3. **ไม่เสียโควตาเพิ่ม:** ฝั่งคำถามยังเรียก AI ครั้งเดียวเท่าเดิม ฝั่งเมนูไม่เรียก AI เลย
4. **ใช้รูปฟรีถูกลิขสิทธิ์:** เก็บไว้ในเครื่อง พร้อมระบุที่มาของแต่ละรูป

## ไม่ทำ

- ไม่ให้ AI สร้างรูปเอง และไม่ส่งรูปเข้าไปให้ AI ดู
- ไม่ดึงรูปจากเน็ตตอนใช้งานจริง (เครื่องอาจไม่มีเน็ตดี และอาจติดลิขสิทธิ์)
- ไม่เพิ่มหมวดร้านอาหารรอบนี้ (ยังไม่มีข้อมูล เป็น call ของผม เพิ่มทีหลังได้)
- ไม่เปลี่ยนปุ่มเรื่องวิทยาลัย (สาขา / คุณสมบัติ / ติดต่อ) ยังกดแล้วถาม AI เหมือนเดิม
- ไม่แตะกฎกันตอบมั่วใน `ai.py`

## สิ่งที่ห้ามเกิด (ถึงโค้ดจะรันได้ก็ถือว่าพัง)

- **รูปไม่ตรงกับสถานที่:** เช่น ถามน้ำตกเจ็ดสาวน้อยแต่ขึ้นรูปน้ำตกอื่น หรือขึ้นรูปวัดอื่นแทน แบบนี้เท่ากับตอบมั่วด้วยรูป ซึ่งเป็นสิ่งที่โปรเจกต์ยอมไม่ได้ ถ้าไม่แน่ใจว่าเป็นรูปของที่นั้นจริง **ไม่ต้องใส่รูป**
- **คำถามเรื่องวิทยาลัยมีรูปที่เที่ยวโผล่มา:** หรือแผนผังวิทยาลัยหายไป (`wants_map` เดิมต้องทำงานเหมือนเดิม)
- **กดเมนูแล้วเรียก AI:** ทำให้เปลืองโควตา

## สิ่งที่ตัดสินใจแล้ว (user เลือก)

- **รูปขึ้นทั้งตอนถามและตอนกดเมนู:** ตอนถามคือแค่พูดถึงสถานที่รูปก็ขึ้น ไม่ต้องพูดว่า "ขอดูรูป"
- **ชั้นสุดท้ายของเมนู:** แสดงรายชื่อพร้อมรูปจากไฟล์ ไม่ใช่ให้หุ่นพูดแนะนำผ่าน AI
- **รูปหาจากแหล่งฟรี:** ให้ผมหาให้

## รายละเอียดการทำงาน

### ข้อมูล (`robot/saraburi_data.json`)

ใส่ฟิลด์เพิ่มให้แต่ละรายการ (ทั้งสถานที่และ OTOP) ฟิลด์ใหม่ทุกตัวไม่บังคับ รายการไหนไม่มีก็ยังใช้งานได้

- `"รูป"`: ชื่อไฟล์ เช่น `"jedsaonoi.jpg"` อยู่ใน `robot/web/static/places/` ถ้าหารูปไม่ได้ก็ไม่ใส่ฟิลด์นี้
- `"ชื่ออังกฤษ"`: ไว้แสดงในโหมด EN และจับชื่อในคำตอบภาษาอังกฤษ (call ของผม)
- `"ชื่อเรียกอื่น"`: ลิสต์ชื่อสั้นหรือชื่อที่คนเรียกกัน เช่น `["เจ็ดสาวน้อย"]` ไว้จับคำถาม (call ของผม)

ข้อมูลที่มาของรูปไม่ต้องใส่ใน JSON นี้ ให้แยกไปไว้ที่ `robot/web/static/places/CREDITS.md` แทน (ไฟล์ รูปของอะไร คนถ่าย สัญญาอนุญาต ลิงก์ต้นทาง) เพราะ `saraburi_data.json` ทั้งไฟล์ถูกส่งเข้า prompt ของ AI ข้อมูลเครดิตจะกิน token เปล่า ๆ

หมายเหตุเรื่องโควตา: ฟิลด์ใหม่ทำให้ prompt ยาวขึ้นเล็กน้อย แต่ free tier จำกัดที่**จำนวนครั้ง** ไม่ใช่จำนวน token จึงไม่กระทบ แต่ถ้าทำได้ง่าย ผู้สร้างจะตัดฟิลด์ `รูป` ออกก่อนส่งเข้า prompt ก็ได้ ตัดสินใจเองได้

### หน่วยจับคู่รูป (โมดูลใหม่ เช่น `robot/web/places.py`)

- โหลด `saraburi_data.json` แล้วสร้างรายการ `(ชื่อทุกแบบ → รายการ)`
- `photos_for(question, answer, lang) -> list[dict]` คืนลิสต์ `{"src", "name", "caption"}` ไม่เกิน 3 รูป
  - **ลำดับ 1:** ชื่อที่อยู่ใน**คำถาม** ถ้าเจอให้ใช้แค่ชุดนี้
  - **ลำดับ 2:** ถ้าคำถามไม่มีชื่อ (เช่น "สระบุรีมีที่เที่ยวที่ไหนบ้าง") ให้ใช้ชื่อที่อยู่ใน**คำตอบ** ตามลำดับที่ปรากฏ
  - เอาเฉพาะรายการที่มีไฟล์รูปอยู่จริง
  - จับชื่อแบบเจอทั้งคำ ระวังชื่อซ้อนกัน เช่น "น้ำตกมวกเหล็ก" กับ "อำเภอมวกเหล็ก" ให้จับชื่อที่ยาวที่สุดก่อน และอย่าให้ชื่ออำเภอในฟิลด์ `อำเภอ` ทำให้จับผิด
- ถ้า `wants_map(question)` เป็น True ให้ใช้แผนผังเดิม ไม่ต้องหารูปที่เที่ยว (ปกติไม่ชนกันอยู่แล้ว เพราะ `wants_map` กันคำนอกวิทยาลัยไว้แล้ว)

### เซิร์ฟเวอร์ (`robot/web/server.py`)

- **`/ask/stream`:** บรรทัดสุดท้ายตอนนี้คือ `{"done": true, "image": ...}` ให้เพิ่ม `"photos": [...]` คำนวณ**หลัง**ได้คำตอบครบแล้ว ส่วน `image` (แผนผัง) ให้คงไว้เหมือนเดิม
- **`/ask`:** เพิ่ม `photos` ใน JSON แบบเดียวกัน
- **`GET /menu`:** ส่งโครงเมนูที่สร้างจาก `saraburi_data.json` (หมวด → รายการ ชื่อไทย/อังกฤษ อำเภอ จุดเด่น รูป) หน้าจอโหลดครั้งเดียวตอนเปิด ไม่เรียก AI

### หน้าจอ (`robot/web/static/screen.html` / `screen.js`)

- **รูปในคำตอบ:** หลัง stream จบ ถ้ามี `photos` ให้แสดงใต้บับเบิลคำตอบ
  - รูปเดียว: แสดงใหญ่เต็มความกว้างบับเบิล
  - หลายรูป: แสดงเป็นแถวรูปเล็ก มีชื่อใต้รูป
  - กดรูปแล้วขยายเต็มจอ ใช้กลไกเดียวกับที่กดขยายแผนผังตอนนี้
- **เมนู:** ปุ่ม 🏞️ ที่เที่ยวสระบุรี กับ 🛍️ ของฝากสระบุรี ที่มีอยู่แล้ว เปลี่ยนจาก "ส่งคำถามไป AI" เป็น "เปิดเมนู"
  - **ชั้น 1:** ปุ่มหมวดย่อย คือหมวดตามไฟล์ข้อมูล ตั้งชื่อปุ่มสั้น ๆ เช่น น้ำตก / วัด / ธรรมชาติ / ตลาด / ใกล้วิทยาลัย และ อาหาร-ขนม / หัตถกรรม / สมุนไพร
  - **ชั้น 2:** รายชื่อในหมวดเป็นการ์ดรูปเล็ก + ชื่อ + อำเภอ ถ้าไม่มีรูปให้แสดงไอคอนหมวดแทน
  - **ชั้น 3:** การ์ดรายละเอียด รูปใหญ่ + ชื่อ + อำเภอ + จุดเด่น
  - ทุกชั้นมีปุ่ม "ย้อนกลับ" และปุ่มกลับหน้าแรก
  - ข้อความทั้งหมดดึงจาก `/menu` ไม่เรียก AI รองรับ TH/EN ตามสวิตช์ภาษาเดิม (ถ้าไม่มีชื่ออังกฤษ โหมด EN แสดงชื่อไทย)
  - (call ของผม) เมนูแสดงเป็นข้อความของหุ่นในแชท ต่อกันไปเรื่อย ๆ เหมือนบอทแชท ไม่ใช้หน้าต่างลอย เพราะเข้ากับจอสไตล์ Gemini ที่มีอยู่ และย้อนดูได้ ถ้าลองแล้วไม่สวยค่อยเปลี่ยน
  - ปุ่มเมนูต้องใช้ได้ทั้งในแถบชิปหน้าแรก แถบข้าง (`sideQs`) และแถบล่าง (`dockQs`) ซึ่งตอนนี้ clone มาจากชุดเดียวกัน
  - ขนาดปุ่มต้องกดง่ายบนจอสัมผัส (อย่างน้อยราว 48px)
- **จอหน้า (`/face`):** ระหว่างเปิดเมนูไม่ต้องเปลี่ยนสถานะ (ไม่ใช่ thinking/answering) ส่วนจะให้หุ่นพูดชื่อสถานที่ด้วยเสียงตอนกดหรือไม่ เป็น call ของผม: **ไม่พูด** เพื่อความเงียบและเรียบง่าย

### รูป

- **ที่มา:** หาจาก Wikimedia Commons ก่อน (เอาเฉพาะ CC0 / CC BY / CC BY-SA / Public Domain) ถ้าไม่มี ค่อยดูแหล่งที่บอกชัดว่าใช้ฟรี
- **ต้องแน่ใจว่าเป็นรูปของสถานที่นั้นจริง:** ดูจากชื่อไฟล์ คำอธิบาย และหมวดบน Commons ถ้าไม่ชัดก็ไม่เอา
- **ขนาด:** ย่อเป็น JPEG กว้างไม่เกิน 1024px ไฟล์ละไม่เกินประมาณ 250KB
- **เครดิต:** จดใน `CREDITS.md` ให้ครบ (CC BY ต้องระบุชื่อคนถ่าย)
- รูปของฝาก OTOP น่าจะหาฟรีได้น้อย ไม่มีก็ไม่เป็นไร
- ตอนจบงาน รายงาน user ว่ารายการไหนมีรูป รายการไหนไม่มี

## เทสต์

ต่อยอดจาก `robot/web/test_server.py` ซึ่ง mock `ask_ai` ไว้แล้ว และเทสต์ข้อมูลที่มีอยู่

- `photos_for`: ชื่อในคำถามได้รูปถูกตัว, ชื่อเรียกอื่นจับได้, ถามกว้างได้รูปจากชื่อในคำตอบไม่เกิน 3, ไม่มีชื่อก็ได้ลิสต์ว่าง, รายการที่ไม่มีไฟล์รูปไม่ถูกคืน, ชื่ออำเภอไม่ทำให้จับผิด, คำถามเรื่องวิทยาลัยไม่มีรูป
- `/ask/stream` กับ `/ask`: บรรทัดจบมี `photos` และ `image` แผนผังเดิมยังทำงาน
- `/menu`: โครงถูก ทุกหมวดในไฟล์มีครบ และ**ไม่เรียก `ask_ai`**
- ข้อมูล: ทุก `"รูป"` ใน JSON มีไฟล์จริง และทุกไฟล์ใน `places/` มีเครดิตใน `CREDITS.md`
- เทสต์เดิมทั้งหมด (37) ต้องยังผ่าน

ตอนทดสอบหน้าจอ ให้จำลอง stream ด้วยการ override `fetch` ในหน้า อย่าเรียก Gemini จริง เพราะโควตาวันละ 20

## ให้ผู้สร้างตัดสินใจเอง

- ชื่อไฟล์รูปและชื่อโมดูล
- หน้าตาการ์ดและ CSS ให้เข้ากับโทนมืด/สว่างที่มีอยู่
- วิธีตัดฟิลด์ `รูป` ออกจาก prompt (ทำหรือไม่ทำก็ได้)
- ป้ายชื่อหมวดย่อยแบบสั้น
